## Where we are

The engine is better than the data. `overlaybuilder` is a disciplined, well-tested builder — the "never invent a value" rule is genuinely enforced in code (`normalize.py:303` raises on unknown units rather than mis-scaling), provenance threads through every driver, and the fallback machinery rewrites `source_name`/`source_url` when a mirror answers. But three things undercut it. First, **the KMZ writer was built against a KML spec ATAK does not implement**: ATAK-CIV ingests KML through GDAL/OGR LIBKML, not a KML renderer, so folder visibility, the Sector→Layer→class tree, polygon fills and label scale are all silently discarded — the README's "dense layers start hidden" promise is inert on device. Second, **`validate` is green on the wrong things**: it lints canonical field keys but never lints `layer:`, `icon:`, `alternates:`, duplicate ids, or state-directory names, so four separate classes of silent-wrong-output pass CI clean. Third, **Minnesota — the flagship — is the thinnest state tier in the repo**: 9 of 134 sources, 4 enabled, two of those four on endpoints the catalog's own notes admit are unconfirmed, and the entire county tier is one parcels layer for one of 3,143 counties. Meanwhile MnGeo already publishes statewide compiled county layers that make the hand-written-87-files model obsolete before it starts.

| subsystem | state | biggest risk |
|---|---|---|
| AOI / clipping | works, slow | O(features×vertices) pure-Python PIP: 6.4–16.9 ms/feature measured → 10–15 min CPU per state pack (`aoi.py:242`) |
| Catalog (134 src) | broad, unverified | 58/134 have no `confidence:`; docs say the field is optional, CLAUDE.md rule 1 says it's mandatory |

| normalize | strongest module | `voltage_kv` synthesized from `max_voltage_kv` unmarked; MHz mis-scales to Hz today |
| KMZ writer | correct KML, wrong target | `_esc` isn't an XML escaper; one control byte kills the whole pack |
| ATAK rendering | ~half the doc is wrong | hidden-layers, folder tree, PolyStyle, 50k threshold — all false on ATAK-CIV |
| Icons | 8 shapes, 72 layers | 20 layers visually identical to another; unknown icon name silently renders a circle |
| reconcile | reports false agreement | 9 of 15 entity types share no COMPARE_KEY → every match stamped "agree" |
| doctor / probe | the right idea, unusable | serial over 134 sources, Markdown only, no `--write`, discards `Probe.fields` |

### Phase 3 — Infrastructure layers + custom logos

**Prerequisite, non-negotiable:** the `ICON_NAMES` lint + raise-on-unknown (Tier 3 #20). Today a typo'd glyph renders a plausible circle with no warning — under rule 1, a symbol the author didn't ask for is an invented value. Everything below rides on that safety net.

**Current state:** 8 parametric shapes, 72 layer keys, **only 52 distinct (colour, shape) pairs** — ~11 genuine point-on-point collisions including `nuclear_reactors`/`eoc`, `ems`/`explosives_storage`, `correctional`/`government`. Four LAYER_STYLE keys (`control_areas`, `fuel_storage`, `rail_terminals`, `stream_gauges`) have no source at all. `docs/ATAK.md:23-26`'s shape legend is **already wrong** for ~10 layers.

**Rendering path (recommended):** author glyphs as SVG in `assets/glyphs/`, flatten offline (dev-only `scripts/`) into a committed integer path table, render with a stdlib scanline filler added to `icons.py`. Keeps zero runtime deps, keeps free recolouring (which `style_rules` depends on), and is *faster* than the current 3× supersampler — measured 210 ms for one 128 px icon, and a large build does ~292 renders.

**Ordered steps:**

1. `ICON_NAMES` + `make_icon` raises + `validate` lints icon names. Keep the 8 legacy names resolving to existing `_inside()` geometry so nothing regresses.
2. Fix `docs/ATAK.md`'s legend (it's wrong today, independent of any new work).
3. Add the scanline filler + path table; `make_icon(shape, rgb, size)` signature unchanged, so `convert/kmz.py` is untouched.
4. **Wave 1 glyphs (your named six + two):** dams, power_plants, nuclear (trefoil), repeaters ×3, substations, hospitals.
5. Move colour to a `SECTOR_COLOR` table (Okabe-Ito, CVD-safe) so glyph carries layer identity and colour carries sector — redundant encoding, which is also what makes it colour-blind safe. Today `hospitals ff0000ff` and `schools ff00ff00` are a textbook deuteranope collision.
6. Bump icons to 48–64 px. ATAK sizes icons as raw pixels × scale with **display density explicitly disabled** (`GLBatchPoint3.cpp:254`) — 32 px is ~1.8 mm on a 440 ppi phone.
7. Generate a legend from `LAYER_STYLE` into the KMZ Document description and `docs/ATAK.md`. With 80 glyphs a legend stops being optional, and generating it means it can't drift the way the current one did.
8. Then upgrade `style_rules` semantically — `power_plants` gains `- {when: "fuel ~ (?i)nuclear", icon: trefoil}`. Works today: `fuel` is canonical and `_eval_cond` already does regex.

**Licensing — the only safe sources:**

| set | licence | verdict |
|---|---|---|
| Maki | CC0 1.0 (LICENSE.txt fetched) | ✅ trace freely |
| Temaki | CC0-1.0 (package.json) | ✅ |
| Osmic / osm-carto symbols | CC0 | ✅ |
| Radiation trefoil | 49 CFR 172 App. B / 10 CFR 20.1901 — federal reg, not copyrightable | ✅ **derive from the CFR, never trace ISO 7010** |
| NPS symbol-library | repo LICENSE.txt is a **Mapbox BSD-3** — it does *not* grant the artwork | ⚠️ cite nps.gov + 17 U.S.C. §105 instead; blacklist the arrowhead |
| Font Awesome Free | CC BY 4.0 (icons) — real attribution obligation | ❌ for an MIT pack |
| Bootstrap / Tabler / Lucide | MIT / ISC | ✅ but prefer CC0 to avoid a NOTICE file travelling with every KMZ |

**Decision you own:** the trefoil geometry. The audit's two proposals contradicted each other (1:3 vs 1.5:4.5); the documented construction is central disc radius R, blade inner 1.5R, outer 5R, three 60° blades at 120° spacing — **confirm against the CFR from an unblocked network before coding it.**

**Most likely to go wrong:** you grow to ~80 glyph names without the lint, and typos ship as wrong-but-plausible symbols across 134 sources with no warning anywhere. That is exactly the failure mode rule 1 exists to prevent.

### Phase 4 — Ham & GMRS repeaters

**Licensing decides this phase, and it resolves worse than expected for the obvious sources.**

| source | status | verdict |

*One audit called OSM "the only clean legal path"; verification refuted that — OpenRepeater's CC0 is cleaner.*

**Ordered steps:**

1. Fix the MHz mis-scaling (#6). Non-negotiable prerequisite.
2. Add canonical keys: `freq_out_mhz`, `freq_in_mhz`, `offset_mhz`, `tone_out_hz`, `tone_in_hz`, `dcs_code` (**format `'{}'`** — leading zeros and the N/I suffix are load-bearing; `023N` would become `23.0`), `mode`, `network`, `node_id`, `callsign` (own key — `source_id`'s DEFAULT_FROM list would win otherwise).
3. Add `LAYER_STYLE` + `HEADLINES` rows for `ham_repeaters` / `gmrs_repeaters` in the same commit as the catalog entry. Without both, the layer builds, validates clean, passes all 143 tests, and renders white circles in "Other" with a popup offering `capacity_mw`.
4. Extend `COMPARE_KEYS` (or make it per-entity) **in the same commit** that sets `entity: ham_repeater` — otherwise every OSM-vs-OpenRepeater match within 800 m stamps "agree" while the frequencies differ, which is the entire point of cross-checking. Also decide what "match" means when two repeaters share a mast.
5. Ship `catalog/global/osm_radio.yaml` (new **Radio** sector), `tags: ["communication:amateur_radio:repeater"]`, `elements: nw`. Explicit `fields:` mapping is **mandatory** — `DEFAULT_FROM['frequency_hz']` will not find `communication:amateur_radio:repeater:frequency_out`.
6. Land the `redistributable: false` mechanism (Phase 2 step 1) *before* any token-gated driver.
7. `group_by: [band, mode]`, band derived from `freq_out_mhz` only when it parses. `group_by` isn't linted, so a derived non-canonical key is the low-friction path.
8. GMRS ships OSM-only with an honest note in `provenance.notes` (which renders into every Document): *"GMRS repeater sites are not in any public federal database; the FCC licenses the operator, not the site."*

**Decisions you own:** (a) OpenRepeater in or out (recommend: in, `enabled: false` until someone reads `/terms` live and records the CC0 wording + a record count); (b) whether FCC LMS broadcast comes first — it's public domain, fits the existing `fcc_asr` pipe pattern exactly, upgrades `broadcast_towers` from OSM-only to authoritative, and reuses `erp_w`/`haat_ft` from the repeater field set.

**Most likely to go wrong, two ways:** (1) **Coverage circles.** Don't. ERP and HAAT are absent from essentially every candidate source, so any radius would be a builder-chosen default presented as a source fact — and a green circle in ATAK reads as a coverage guarantee. Put `erp_w`/`haat_ft` in the popup when present, nothing when absent. (2) **Filename churn.** `doc_key` is derived from how many sources share a logical layer (`build.py:277-278`), so the day a second repeater source is enabled, the OSM pack silently renames from `ham_repeaters.kmz` to `ham_repeaters__osm.kmz` — breaking every saved overlay set. Give the OSM source a fixed provider suffix from day one.

**Privacy guardrail to write into CONTRIBUTING.md now:** repeater sources must be operator-published (a sysop listing in OSM/OpenRepeater has published it), never derived by geocoding a licence address, and a removal request from a named licensee is honoured. Most GMRS and many amateur repeaters sit on private residential property; the existing personal-data bullet doesn't cover the reverse direction.

## Refuted / don't bother

- **The MN `service_territories` EUSA endpoint is fine.** `app.gisdata.mn.gov/arcgis/rest/services/EUSA/EUSA/FeatureServer` indexes as a live service; the "wrong host/path pattern" claim was wrong. Adding the `util_eusa` mirror as an `alternates:` entry is still worth doing.
- **MnGeo's GDRS bulk-download pattern is not legacy.** `resources.gisdata.mn.gov/pub/gdrs/` is a live indexed directory and the dataset pages still point at it. Don't rewrite `docs/SOURCES.md` on a deprecation nobody can confirm.
- **`doctor` *can* detect a vanished mapped field** — for all 45 ArcGIS sources (`probe.py:139-163` + "Schema warnings" in `doctor.py:81-88`). The real gap is the inverse: the 19 `file`-driver sources (NID's ~70 columns, EIA-860M's drifting headers) get **no** field check at all, because `_probe_download` only sniffs the first 2 KB.
- **`pyshp` and `pyproj` are not optional.** They're guarded at import but `census_tiger.py:16` imports `_shp` at module top, and boundary layers are mandatory for every county/state AOI — moving them to an extra would break the primary workflow.
- **`release.yml`'s tag parser is correct.** `${REF%%-*}` / `${REF#*-}` split on the first dash only; `pack-region-upper-midwest` and `pack-bbox--97.5,44,-96,45` both parse fine. The real problems are the missing matrix, the missing size budget, and the unpinned action.
- **MIL-STD-2525 / CoT types in a KMZ do nothing.** ATAK resolves 2525 symbology for CoT *markers*, never for KML placemarks. Ship `cot_type` as metadata if you like, but it will not change a single icon.
- **`<open>0</open>` is a no-op on ATAK-CIV** (Google Earth only). So is folder `<visibility>`, `<tessellate>`, `PolyStyle` fill and `LabelStyle` scale.
- **NetworkLink index KMZs buy nothing** on ATAK's OGR path, and PMTiles is the wrong contract — ATAK's KML importer is the delivery mechanism.
- **The NPS symbol-library `LICENSE.txt` is a Mapbox BSD-3** and does not grant the artwork. Cite nps.gov + 17 U.S.C. §105 instead; never rely on that file.
- **ARRL Repeater Directory is RepeaterBook** (the 2026 edition says so on the cover). Not an independent source, and it's a paid print product.
- **FCC ULS cannot give you repeater locations.** Amateur and modern GMRS licences carry a mailing address, not a station site. Don't build the obvious-looking `l_amat` driver.
- **No public national fibre-route dataset exists.** FCC BDC publishes *availability* and modelled mobile coverage, not physical routes; long-haul maps are commercial. Same for NRC materials licensees (a list, not a layer) and USDA grain elevators (already documented as list-only in `chemical_industry.yaml:78-86`).
- **Don't draw repeater coverage circles from HAAT/ERP.** Both fields are absent from every candidate source; a green circle in ATAK reads as a guarantee.
- **Lidar/MnTOPO is out of scope** for a KMZ pack (no raster driver, by design). Derived *vector* products from lidar are in scope and cheap.
- **`Mbpd` is not a live hazard** — both uses are EIA refinery fields documented as thousand-barrels-per-day at the point of use. Still worth one parametrised test pinning all 31 `_UNIT_TO_CANON` factors.
